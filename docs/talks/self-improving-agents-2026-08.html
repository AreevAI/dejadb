Overview / 02 · root cause

"Who owns billing escalations?"

Top-3 from a vector store, ranked by similarity:

0.83"escalate billing issues to John"no timestamp
0.82"Priya owns billing now"no timestamp
0.81"billing escalation was updated"no timestamp
All three go in the prompt

Three scores inside 0.02 of each other — statistically indistinguishable. Two contradict each other; one is only about the change.

Similarity can't tell current from stale. No time axis. No links.

Not a retrieval-quality problem. A better embedding model returns the same three chunks, with the same confidence.
Overview / 03 · the usual fix

Overview / 05 · CAL

The same question — answered once.

CAL, the Context Assembly Language: sources, relevance, budget, format — one statement.

the query
ASSEMBLE "billing escalation" FROM owner: (RECALL facts WHERE subject = "billing_escalation" AND relation = "owner"), policy: (RECALL facts ABOUT "refund window" LIMIT 3 WITH rerank, diversity(0.4), min_score(0.5)), caller: (RECALL facts WHERE subject = "user:maria"), history: (RECALL observations RECENT 3) BUDGET 800 tokens PRIORITY owner: 0.4, policy: 0.3, caller: 0.2, history: 0.1 FORMAT markdown WITH dedup(object)
what the model actually receives all · 5
  • billing_escalation owner Priya live · 2026-08-04
  • refund_policy enterprise_window 45 days for enterprise 0.95 · 2026-08-04
  • refund_policy standard_window 30 days for every tier 0.90 · 2026-08-04
  • user:maria tier enterprise 0.95 · 2026-08-04
  • maria asked why her refund took 9 days observation · 2026-08-04
5 grains · rendered markdown · within an 800-token budget
Assembly logic is data, not code — save the query into the memory file and re-tune what gets injected without redeploying the agent. (Cross-encoder rerank is feature-gated; the lexical + vector legs are the stock path.)

Act II

What "self-improving"
actually means

A lifecycle you can point at — not a property you claim.

Definition / 08

Self-improvement is a lifecycle,
not a vibe.

Most "self-improving agent" demos stop at 03. Rungs 04 and 05 are the difference between a demo and a system.
Definition / 09

Memory ≠ measurable improvement.

Agent memory

Stores facts, events, tool results, goals, state.

"What has the agent
seen before?"

Measurable improvement

Stores a tested lesson, skill, or policy change.

"Did this change make
the agent better?"

Evidence links them. Metrics validate them. Rollback keeps them safe.

Definition / 10

Now let that agent
learn from itself.

A read-only memory gets one answer wrong. A self-improving agent reads the stale fact, distills a lesson from it, and writes that lesson back — where every future decision inherits it.

Confidently wrong — and compounding
Definition / 11 · the asymmetry

Self-judging degrades.
External verifiers compound.

The design rule falls straight out: whatever proposes a change must never be what approves it.

Definition / 12 · why now

The ungoverned version
just became a liability.

Measured in the field

97.8%

of a 10,134-entry production memory store audited as junk after 32 days — including 668 stored copies of a single hallucination. A better extraction model didn't fix it.

Regulation

Art. 12

EU AI Act record-keeping — automatic logs across the system lifetime. Annex III high-risk duties were deferred to Dec 2027. The date moved; the requirement didn't.

Security

Poisoning

Memory injection is a live attack class. Every published defense asks for the same three things: provenance, validation before persistence, rapid rollback.

Field evidence, regulation, and security independently converge on one word: governed.
Act III

Hermes: skills
from experience

How an agent turns a workflow it just completed into one it can reuse.

Hermes / 13

Hermes turns successful workflows
into reusable skills.

Skills are procedural memory: on-demand documents loaded only when relevant, instead of bloating every prompt.

Create

After a complex task, an error recovery, or a user correction, the agent can write a skill.

Reuse

Installed skills are invoked directly and bundled into profiles for recurring work.

Consolidate

A background post-turn review compacts episodic memory into the two capped files.

Built-in memory is deliberately small: MEMORY.md (2,200 chars) + USER.md (1,375) + an FTS index over session history.
Hermes / 14 · where the gate is

The gate ships off.

hermes config — defaults
memory.write_approval false skills.write_approval false

Both default to false — write freely. An open feature request (#19324) asks for approval-before-write, which tells you users want the gate.

And when a capped file fills, consolidation replaces entries — the previous wording is gone from disk. "What did this agent believe last month?" has no answer.

Stated from its own documentation. An observation about design — not about quality or adoption.

Substrate / 18 · scope

What we're claiming — and what we're not.

In scope

The agent's memory

What it knows. Is it current, consistent, non-duplicated, evidence-backed, and reversible?

Out of scope

The agent's outputs

We make no claim that this "makes your agent better at tasks." That's a capability claim, and it needs a capability measurement.

Clean, current, contradiction-free memory is the mechanism — not the outcome. We stop where the measurement stops.

Deterministic analyzers compute over typed grains — error flags, supersession chains, valid_to windows — never over raw prose. If your memory is a pile of text, you have no choice but to pay a model to tell you what's in it.

Waiser / 20 · detection

Eleven analyzers. Ten on by default.

Hygiene — is memory correct?

  • tool_failure — recurring failure clusters → a lesson
  • duplicate_sweep — exact + near dupes → consolidate
  • contradiction_sweep — two live values, one relation
  • staleness — past valid_to → forget, human-gated
  • fork_surfacing · skill_stall · outcome_review

Utility — does memory earn its place?

  • cold_grains — facts that are never recalled
  • coverage_gap — questions that keep returning empty
  • budget_pressure — context budget overflowing
  • fed by a disposable recall-telemetry sidecar

Telemetry is buffered and non-blocking — voice-loop recall stays ~82µs p50 with it on, encrypted under the file's key, and it never syncs. Add your own check in any language with --analyzer-cmd — advisory only, it can never mutate memory.

Waiser / 21 · what it produces

Recommendations, not prose.

The signature is normalized (call:#) so five error strings cluster into one finding. It fires on rate, not just count. And rollbackable:true means the inverse was computed and stored at apply time.

Waiser / 22 · the four gates

Nothing changes behind your back.

Auto-apply is off by default — granted only by a host policy file, only for built-in analyzers, only non-destructive curation, never for LLM findings. Exactly one analyzer is even eligible.

Waiser / 23 · correction

Correcting knowledge shouldn't erase it.

Last-writer-wins

The new value overwrites the old. The previous belief is gone. "What did it think last month?" — unanswerable.

Supersession

The new value is live; the old is retained and marked. The link carries the reason and the actor.

Auditors don't want your current state. They want the chain — and the chain is what makes "what did this agent believe on 3 August, and why" an answerable question.

When content genuinely must go: forget is a single-grain, gated tombstone. And we say the hard part out loud — logical deletion isn't byte erasure in any SQLite-lineage engine. The only honest erasure is crypto-erasure: destroy the key.

Waiser / 24 · measurement

"Did it change something" is the wrong question.

"Did the change help?" is the product.

deja waiser outcomes
a6f8133 tool_error_recurrence @1d baseline 0 → current 0 [held] a6f8133 tool_error_recurrence @7d baseline 0 → current 0 [held] a6f8133 tool_error_recurrence @30d baseline 0 → current 2 [regressed] → revert proposed

A fix that looks fine early and rots later is exactly the one that hurts you. A single post-apply check would have called this a success on day one.

Re-measurement is a typed read over subsequent history — no LLM, no judge model, no guessing.

Honest boundary: this works for bounded, attributable outcomes — did that failure recur, does that duplicate still exist. It does not score "was the blog post good."

Proof / 26 · the model layer

Determinism finds. The model extends.
A verifier decides what you see.

Discover

Abstention is legitimate — "NOTHING TO REPORT" scores zero penalty, so the model isn't pushed to invent findings.

Ground

Premises must exist in the cited, content-addressed grains. Anti-fabrication — it checks premises, not conclusions, so real inference still passes.

Verify

An independent call judges soundness. The proposer never grades itself. Grounding can run on a different model entirely.

Route

Survivors carry origin = llm. They reach the queue — and they can never auto-apply.

No backend configured? The stages become the identity function and the deterministic loop is unchanged. The floor is always keyless.

Act VII

Architecture for
enterprise agents

Trust boundaries, failure modes, and operations — not just recall quality.

Enterprise / 29

Six things to get right.

Blast radius

One memory = one file

The unit of erasure, sync, portability, and write parallelism. File-per-tenant falls straight out.

Trust boundary

The host executes tools

Memory stores evidence, never actions. The memory layer cannot take an action.

Separation of duties

Scopes, not conventions

Reviewer and worker processes get different scopes — so an agent cannot approve its own proposals.

Auditability

The audit trail is data

One immutable, hash-chained grain per transition with actor and reason. It syncs with the file and it's queryable.

Policy as code

Autonomy is granted, never assumed

The policy file rejects unknown keys and is never stored in the memory file — a stolen file can't arrive pre-armed.

Operations

No daemon, no scheduler

It rides your hooks, cron, or CI. One binary. Works air-gapped.

Enterprise / 30

No daemon. It rides what you already run.

triggers — cheap, idempotent, watermark-gated
$ deja waiser run --min-new 20 --min-new-errors 3 --if-stale 6h ↳ a session-end hook · cron · CI · an MCP call at session start $ deja waiser list --fail-on high ↳ exits 2 when a high-severity recommendation is pending — build-blocking memory review

Surfaces: deja waiser CLI · Python & Node bindings · two MCP tools (reviewer and worker get different scopes) · /api/waiser/* · a web console with the queue, sessions, and outcomes.

Enterprise / 31 · non-goals

What this does not do.

NOT Make your agent better at tasks. It improves memory, not outputs.
NOT Rewrite your system prompt, skills, or code autonomously.
NOT Inject itself into a prompt you didn't wire it into. Every host pulls.
LIMIT The grounding checker is right ~3 in 4 on hard cases. A strong filter — not an oracle. The human gate stays.
It's not "AI-powered" at the core. The deterministic layer is the floor; the model is an optional, bounded extension.
